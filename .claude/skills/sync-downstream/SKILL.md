# Sync the downstream repos

`platform.yaml → downstream` lists each repo (checked out next to this one) and which generated file goes where. `./base sync` copies them; it never edits code in those repos. Wiring the files in is done once per repo, by hand, as below. Each downstream repo has a `base-platform` skill describing its side.

```bash
./base gen
./base sync --check      # what is out of date
./base sync              # copy (only repos that are checked out next to baseApp)
```

Then, per repo, on its own development branch:

## Burrow (Android-Showcase)

- Gets `BaseTokens.kt` (package `base.platform.tokens`) and `assets/base/models.json`.
- Burrow's `ui/theme/Theme.kt` holds the same values today. To make the base the source: have `BurrowColors` Light/Dark read `BaseTokens.Light.*` / `BaseTokens.Dark.*`, and `Hand.*` sizes read `BaseTokens.HandType.*`. Then a token change reaches Burrow with a sync and a build.
- New doodles: copy the path string from `design/doodles.json` into `ui/hand/Doodles.kt` (same format).
- New shared components: port the Flutter widget to Compose in `ui/hand/HandUi.kt`; the drawing helpers (`wobble`, `handLine`, `swipe`, `handCircle`) are already identical.
- Verify: `./gradlew :app:testDebugUnitTest --tests '*DesignSystemTest*'` and compare `app/build/shots/00-design-system*.png`.

## PhoneDots

- Gets `assets/base/models.json` and `lib/theme/base_tokens.g.dart`.
- PhoneDots is Flutter: the real fix is to migrate it onto the packages (depend on `base_models` for the hub and `base_design` for the look) so it gets every change automatically. Until then, compare its `lib/core/models/model_catalog.dart` with the synced JSON and update ids, URLs and checksums by hand.
- Verify: `flutter analyze && flutter test`.

## Spreix (spreix-notetaker-apps)

- Gets `src/styles/base-tokens.css` (CSS variables `--base-*`, dark via `data-theme="dark"` or the OS) and `src/base/models.json`.
- Most of Spreix's UI is generated by `npm run sync:ui` from the main repo, so tokens can only be used in its own files (`src/app-shell`, `src/native`, ...) unless the main repo adopts them. Import the CSS once in the app shell and use the variables in hand-written components.
- Doodles as SVG: `generated/svg/doodles/*.svg` (stroke `currentColor`).
- Verify: `npm test && npm run typecheck && npm run build`.

## After syncing

Commit in each downstream repo with a message naming the base version (`design/tokens.json → version`) and what changed. Never push those repos without the user asking; they have their own branches and reviewers.
